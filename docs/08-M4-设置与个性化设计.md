## 1. 目标与非目标

### 目标

1. **设置页骨架**：一个三端统一的设置入口与面板（桌面模态 / 手机全屏），分组导航，未配置 vault 时也可用
2. **外观可调**：界面 / 正文 / 等宽三类字体、正文字号、源码字号、行距、正文宽度——改完**立即生效且不重建编辑器**
3. **编辑器偏好**：默认打开模式、自动保存延迟、源码模式行号、新建笔记默认位置
4. **存储管理**：当前 vault 路径与统计、切换笔记库（安全流程）、在系统文件管理器中打开、重新扫描、回收站占用与清理策略
5. **同步与关于页聚合**：自动同步开关（与侧栏同一状态）、设备配对入口、版本 / 配置目录 / 日志目录 / 恢复默认

### 非目标（明确不做，避免范围膨胀）

| 项 | 推迟到 | 说明 |
|---|---|---|
| **暗色主题** | 二期 | 2026-09-21 用户定 **不做**。Crepe 浅色全靠 `index.css` 高优先级覆盖（AGENTS.md 硬约定 7），换肤等于重做一整套覆盖；M4 连分组占位都不留 |
| **自动同步周期可配置** | 二期（维持 docs/07 §1 结论） | 2026-09-21 用户定 **不做**：周期固定 60s，设置页不出现该控件，docs/07 §7 触发器 A 的门槛不变 |
| **vault 备份 / 整体导出** | 二期 | 2026-09-21 用户定 **不做**：原 P2 的「目录复制导出」一并取消，不引 zip 依赖；M4 存储组只保留路径 / 统计 / 换库 / 回收站 |
| 字体文件导入 / 内置字体 | 二期 | 不打包字体（APK 体积 + 授权）；只做系统字体栈 + 自定义字体名（可用性由系统决定） |
| 快捷键自定义 / 命令面板 | 二期 | M4 无键盘映射抽象 |
| 插件系统、主题市场 | 二期 | 不在 MVP 路线（docs/02 §4 二期候选） |
| 多 vault 快速切换（最近列表） | 二期 | M4 只做「切换」动作本身，不建 vault 历史 |
| 导出 PDF/HTML、标签、双链 | 二期 | docs/02 二期候选 |
| i18n（多语言界面） | 二期 | M4 界面文案保持中文 |
| 自签 TLS + 证书固定 | M4 另一条线 | docs/02 §4 M4「安全加固」，与设置页无关，单独立项 |
| **界面缩放（UI scale）** | **M4b-P2（视余力）** | rem 基准缩放会连带侧栏宽度变化，风险见 §9 R7 |

## 2. 对标：其他笔记软件怎么组织设置

来源为对各产品设置面板的既有认知（非逐项实测），用于**取值与分组的取舍参考**，不作为精确事实引用。

| 产品 | 设置分组 | 字体/字号能力 | 存储能力 | 对 Lanmark 的启发 |
|---|---|---|---|---|
| **Obsidian**（本地 md，最接近） | 常规 / 外观 / 编辑器 / 文件与链接 / 快捷键 / 核心插件 / 社区插件 / 同步 / 关于 | **界面字体 / 正文字体 / 等宽字体 三档分离**，字体下拉取自系统字体；正文字号滑块；缩放 slider；可读行宽开关 | 库切换（多库列表）、附件位置、回收站（系统/库内）、删除策略 | **三档字体 + 字号调节 + 行宽开关**是最被验证的组合，Lanmark 采用相近结构（字号按 D4 用户决策改为四档） |
| **Joplin**（md + 端到端同步） | 常规 / 外观 / 笔记 / 同步 / 加密 / 插件 / Markdown | 主题（浅/暗）+ 编辑器字号 + 字体族 | 数据目录显示、导出（JEX/MD/raw）、回收站/笔记历史 | 「数据目录显示 + 导出」值得有；**加密**不采纳（M4 无账号体系） |
| **思源笔记**（块级、本地优先） | 外观 / 编辑器 / 账号 / 云端 / 导入导出 / 关于 | 主题 + 字号（含 UI 字号）+ 字体 | 工作空间路径、导出、数据快照 | 「UI 字号」需求真实存在，但 Lanmark 列为 P2（见非目标） |
| **有道云 / Notion**（云笔记） | 极简：账户 / 快捷键 / 主题 / 通知 | 通常只有「字号（小/中/大）」或无 | 无（云托管） | 反面参照：Lanmark 是**本地文件优先**，存储类设置必须有（路径、回收站、备份） |

**结论（取舍原则）**：

1. **本地优先 ⇒ 存储组必须重**：云笔记没有「库在哪、回收站多大、怎么备份」的烦恼，Lanmark 有，这是本项目设置页与其他软件最大的差异点
2. **字体只做「方案」不做「字体选择器」**：三端字体可用性不同（Android 只有 Noto/Roboto，Win 是 Segoe/雅黑，Linux 靠 Noto），与其列 20 个不可用的名字，不如给 4 档语义方案（系统默认 / 无衬线 / 衬线 / 自定义）+ 回退栈
3. **不做暗色**（2026-09-21 拍板）：成本全在 Crepe 覆盖（硬约定 7），M4 只交付浅色「晨窗」的可调项（字体 / 字号档位 / 行距 / 行宽）
4. **同步不重做一套 UI**：M3 已在侧栏 SyncSection 落地「常驻条 + 上拉面板」（用户选定方案 B），设置页只放开关与入口，避免两处分叉

## 3. 配置项清单（最终决定）

> 默认值 = 与当前实现视觉等价（改完默认设置，界面不变），保证升级无感。

### 3.1 外观（Appearance）

| # | 配置项 | 取值 | 默认 | 作用范围 | 备注 |
|---|---|---|---|---|---|
| A1 | 界面字体 | `system` / `sans` / `serif` / `custom` | `system` | 侧栏、头部、对话框、面板（**不含**编辑器正文） | 只改 `--font-sans` 运行时值 |
| A2 | 正文字体 | 同上四档 | `sans` | WYSIWYG 正文、标题、阅读模式 | `--crepe-font-default` / `--crepe-font-title` |
| A3 | 等宽字体 | `system` / `mono` / `custom` | `system` | 代码块、内联代码、源码模式 | `--crepe-font-code` + `.cm-editor` |
| A4 | 正文字号 | **四档** 小 14 / 中 16 / 大 18 / 特大 20 px | `md`（= 16px，与现状一致） | 编辑器正文 + 阅读模式 | `--crepe-base-font-size` 与 `.ProseMirror` 同步 |
| A5 | 源码字号 | **四档** 小 12 / 中 14 / 大 16 / 特大 18 px | `md`（= 14px，现硬编码 13.5 → 取整） | CodeMirror 源码模式 + 块内代码 | 消除 `index.css` 的 13.5px 硬编码 |
| A6 | 行距 | `compact` 1.55 / `normal` 1.75 / `relaxed` 2.0 | `normal` | ProseMirror 行高 | 枚举而非自由数值，避免畸形排版 |
| A7 | 正文宽度 | `auto`（跟随窗口） / `limited`（≤820px） | `auto` | `.editor-host .milkdown` 的 max-width | 宽屏桌面防「一行太长」 |
| A8 | 界面缩放 | 100 / 112 / 125 % | `100` | rem 基准 → 全站 UI | **P2**，风险见 §9 R7 |

**字体方案 → CSS 栈映射**（`src/lib/settings.ts` 单一来源，Rust 只存 key）：

| key | 字体栈 |
|---|---|
| `system` | 沿用 `index.css` 现有 `--font-sans` / `--font-mono` 原栈（当前视觉） |
| `sans` | `"Noto Sans","PingFang SC","Microsoft YaHei","Segoe UI",system-ui,sans-serif` |
| `serif` | `"Noto Serif CJK SC","Source Han Serif SC","Songti SC","SimSun",Georgia,serif` |
| `mono` | `"JetBrains Mono","Cascadia Code","Noto Sans Mono CJK SC",ui-monospace,monospace` |
| `custom` | 用户字符串，落库前过白名单（§4.3） |

**字号档位（`SIZE_SCALE`，2026-09-21 用户定：档位而非连续滑块）**：正文与源码共用同一枚举 `sm|md|lg|xl`，各查自己的映射表。

| 档位 | 正文 `text_size` | 源码 `code_size` |
|---|---|---|
| 小 `sm` | 14 px | 12 px |
| 中 `md`（默认） | 16 px | 14 px |
| 大 `lg` | 18 px | 16 px |
| 特大 `xl` | 20 px | 18 px |

为什么不用滑块：三端屏幕与 DPI 跨度大（手机 385px 逻辑宽 ↔ 桌面 1080–4K），档位让「多大算大」有稳定语义、便于真机走查逐档截图对比；且 Rust 侧可枚举校验（非法值回退 `md`），比 clamp 数值区间更不易出畸形排版。源码档位整体比正文小 2px，保持「代码略小于正文」的既有视觉关系。

## 4. 配置存储设计

### 4.1 存哪：设备级 → `app_config_dir/config.json`

| 候选 | 结论 | 理由 |
|---|---|---|
| `AppConfig`（`app_config_dir/config.json`） | ✅ **采用**（字体/字号/编辑器/存储策略/同步） | 已有 `load_config`/`save_config`（**tmp+rename 原子写**）、已有 `syncAuto` 扩展先例、已有「读旧配置只改目标字段」纪律；**跨 vault 生效**（字体是设备偏好，换库不该变）；Android WebView 清数据不会丢 |
| vault 内 `.lanmark/settings.json` | ❌ | `.lanmark/` 不参与同步（硬约定 4 派生：vault 文件是唯一事实源，元数据是设备本地），且会导致「换库后字体变了」的反直觉行为；还会让设置进同步清单判定 |
| `localStorage` | △ 仅保留现状 | `collapsedDirs`（vault 级视图状态）继续 localStorage 不动；**新设置一律不进 localStorage**（Android WebView 存储可被清理，且不可测） |

**分界规则（写进 AGENTS.md 硬约定候选）**：*设备/用户偏好 → `AppConfig`；vault 级视图状态（折叠、当前笔记）→ localStorage；笔记内容 → 文件。*

### 4.2 数据结构（Rust）

```rust
// src-tauri/src/vault.rs（AppConfig 内嵌，全部 serde(default) ⇒ M3 及更早的 config.json 直接可读）
pub struct AppConfig {
    pub vault_path: Option<String>,
    pub sync_auto: bool,                       // M3 既有
    #[serde(default)] pub appearance: Appearance,
    #[serde(default)] pub editor: EditorPrefs,
    #[serde(default)] pub storage: StoragePrefs,
    // 同步周期不做（D2 取消）：周期固定 60s，仍是 docs/07 §7 的常量，不进配置
}

#[derive(Debug, Serialize, Deserialize, Clone)]
#[serde(rename_all = "camelCase", default)]
pub struct Appearance {
    pub ui_font: String,        // "system"|"sans"|"serif"|"custom"
    pub text_font: String,      // 同上
    pub mono_font: String,      // "system"|"mono"|"custom"
    pub custom_fonts: CustomFonts,  // { ui: Option<String>, text: …, mono: … } 空串 = 未设置
    pub text_size: String,      // "sm"|"md"|"lg"|"xl"，默认 md（16px，§3.1 档位表）
    pub code_size: String,      // 同上，默认 md（14px）
    pub line_height: String,    // "compact"|"normal"|"relaxed"，默认 normal
    pub content_width: String,  // "auto"|"limited"，默认 auto
    pub ui_scale_pct: u16,      // 100|112|125，默认 100（P2）
}

pub struct EditorPrefs { default_mode, autosave_ms, source_line_numbers, new_note_location }
pub struct StoragePrefs { trash_retention_days: u32 /* 0=从不，默认 30 */ }
```

### 4.3 校验与命令（Rust）

| 命令 | 纯逻辑 `_op` | 说明 |
|---|---|---|
| `settings_get() -> Settings` | `settings_read_op` | 只读 `AppConfig`，**不依赖 vault**（未配置库时设置页也可用） |
| `settings_patch(patch) -> Settings` | `settings_apply_op` | patch 字段为 `Option<小节>`：**传入即整体替换该小节**（前端持有完整对象，天然表达「清除自定义字体」= 传空串，避开 `Option<Option<T>>` 三态）；**逐字段 clamp / 归一**后落盘并**返回归一化结果**（前端以返回值为准） |
| `settings_reset() -> Settings` | `settings_reset_op` | 恢复默认，保留 `vault_path`（E4） |
| `vault_stats() -> VaultStats` | `vault_stats_op` | 笔记/文件夹/附件计数 + `bytes` + 回收站条目/占用；无 vault 时报错 |
| `trash_clear() -> usize` | `trash_clear_op` | 清空 `.lanmark/trash`，返回删除条目数 |
| `trash_prune(days) -> usize` | `trash_prune_op` | 按文件名前缀 `<ms>-` 解析时间清理；调用点 = 开库 reindex 后 + 设置页「立即清理」 |
| `app_info() -> AppInfo` | — | version / platform / configDir / logDir（E1） |
| `open_in_file_manager(path)` | — | 桌面限定（`@tauri-apps/plugin-opener`），Android 不注册按钮 |
| `vault_export(dest) -> usize`（P2） | `vault_export_op` | 目录复制；导出前 flush + 暂停自动循环（§9 R8） |

**字体串白名单（安全要点）**：自定义栈仅允许 `[A-Za-z0-9 ,\-_"'()]+`、长度 ≤ 200，含 `;{}<>@!\/` 等一律拒绝并回退 `system`。原因：该串最终写进 `:root` 的 CSS 变量，未过滤可构造声明注入（如 `x; --c-ink: red`）。校验放 Rust（`_op` 可单测）+ 前端输入侧同步提示。

**写盘纪律**（沿用 `vault_set_sync_auto`）：`load_config` → 改字段 → `save_config`（原子写）；**绝不整体覆盖 `vault_path`**。

### 4.4 前端：`src/stores/settings.ts`（Zustand，与 vault/sync 同构）

- 状态：`settings`（归一化对象）+ `loading` + `error`
- `load()`：App 启动时与 `vault.init()` 并行调用；拿到结果立即 `applyCssVars()`
- `patch(section)`：**乐观更新 → 应用 CSS 变量 → 调 Rust → 以返回值覆盖**（失败则回滚上一版变量 + 错误提示）
- `applyCssVars()`：唯一写入点，`document.documentElement.style.setProperty` 写：
  `--lanmark-font-ui / --lanmark-font-text / --lanmark-font-mono / --lanmark-text-size / --lanmark-code-size / --lanmark-line-height / --lanmark-content-max`

**CSS 改造点（`src/index.css`）**：

| 位置 | 现状 | 改为 |
|---|---|---|
| `@theme inline` 的 `--font-sans` / `--font-mono` | 静态栈 | 运行时可被 `:root` 覆盖（`@theme inline` 的 utility 引用变量，天然支持） |
| `.milkdown` 的 `--crepe-font-default` / `-title` / `-code` | `var(--font-sans/mono)` | `var(--lanmark-font-text)` / `var(--lanmark-font-mono)` |
| `.milkdown` 的 `--crepe-base-font-size` | 硬编码 16px | `var(--lanmark-text-size)` |
| `.editor-host .milkdown .ProseMirror` | 无字号/行高声明 | 补 `font-size: var(--lanmark-text-size); line-height: var(--lanmark-line-height); font-family: var(--lanmark-font-text);`（**更高 specificity，符合硬约定 7**） |
| `.cm-editor { font-size: 13.5px }` | 硬编码 | `var(--lanmark-code-size)` |
| `.cm-editor .cm-scroller { font-family: var(--font-mono) }` | 静态 | `var(--lanmark-font-mono)` |
| `@media (max-width: 767.98px)` | 只调 padding | **保持只调 padding**：字号一律由变量驱动，窄屏不得再写死字号（消除硬约定 6 的一处潜在双源） |

**关键：改设置不重建编辑器。**`MilkdownHost` 的 `key` 只由 `路径|模式` 决定（抽成纯函数 `editorKey(path, mode)`，便于单测断言），字体/字号**不进 key**——Crepe 实例不销毁重建，因此不会触发创建期的伪 `markdownUpdated`，也就不会「改个字号就把笔记重写一遍」（硬约定 3）。

## 6. 关键流程

### 6.1 切换笔记库（C3，最高风险）

```
1. dirty → saveNow()；失败 → 中止并提示（未保存编辑不丢铁律，同 deleteNode 守卫）
2. stopAutoLoop()               ← 先停循环，防止回合打到半切换状态
3. 选择目录（桌面 dialog / Android 应用目录 / Android 自定义路径 + MANAGE 校验）
4. vault_set_path / (_ensure_dir) —— 与 VaultPicker 完全相同的调用路径
5. 成功：status=ready、activePath=null、content=""、refreshTree + refreshMeta、
   collapsedLoadedFor 失效（重载该库折叠状态）、按 B1 设默认模式
6. 手机端：open_vault_at 的 #[cfg(target_os="android")] 分支会 spawn 服务器（幂等，
   端口可能 +1）→ 提示「同步中心已重启，配对码不变，桌面无需重新配对」
7. 失败：保留原 vault 与状态 + 错误 toast（不得出现「已切库但树是旧的」）
8. App.tsx 的 effect 按 status 自动重启循环（无需手动 restart）
```

### 6.2 回收站清理（C6）

- 保留策略：`trash_retention_days`（默认 30，`0` = 从不）；解析 `.lanmark/trash/<ms>-<name>` 的 ms 前缀判定过期
- 触发点：开库 reindex 之后（惰性，不阻塞首屏）+ 设置页「立即清理」
- 「清空全部」：二次确认显示条目数与占用 → `trash_clear` → 刷新统计
- 与 tombstone 无关，文案显式区分（§3.3 注）

### 6.3 设置应用与回滚

```
UI 改动 → 乐观 set state → applyCssVars（立即可见） → settings_patch → 返回值覆盖 state
        └→ 失败：回滚为上一版 state + applyCssVars(previous) + error toast
```
字体串不合法时由 Rust 归一为 `system`，前端以返回值为准并提示「自定义字体未生效，已回退系统默认」。

## 12. M3 验收遗留项（2026-09-23 写入 M4 开发规划）

> 来源：M3 验收（docs/07 §11e/§11f，REDMI K90 / Android 16）及其后的 CDP 走查。两项：§12.1 是 M4 开发项（**M4g 发版线**，与设置页主线独立、建议 M4f 验收前完成）；§12.2 经确认**设计使然、非缺陷**，只落文档注明（AGENTS.md 发版一节已同步注明）。

### 12.1 CI 固定 release keystore（M4g）

**问题（M3 验收发现）**：`release.yml` 的 android job 用 `pnpm tauri android build --debug` 构建后仅重命名为 `lanmark-android-aarch64.apk`。debug keystore 由 AGP 在每台 CI runner 上首次构建时随机生成（runner 每次全新）→ **每个 release 的 APK 签名都不同** → 手机覆盖安装失败（INSTALL_FAILED_UPDATE_INCOMPATIBLE），用户只能卸载重装。对「使用应用目录」的用户（vault 在应用私有存储，`vault_picker_app_dir` → `appDir`），**卸载 = 本地 vault 整体丢失**；SAF 自定义目录用户不受影响。仅 Android 受影响（Linux 原生二进制 / Windows NSIS 无签名覆盖安装问题）。

**方案**：

1. **生成 keystore（仅一次，仓库管理员操作）**：本机 `keytool -genkeypair -v -keystore lanmark-release.keystore -alias lanmark -keyalg RSA -keysize 2048 -validity 10000`（有效期 10000 天 ≈ 27 年，覆盖产品生命周期）。**keystore 文件永不入库**——它是私有密钥材料，与硬约定 9 的 `patches/` 性质相反（patches 是公开源码必须入库；keystore 入库等于公开签名权）。
2. **配 4 个 GitHub repo secrets**（GitHub → Settings → Secrets and variables → Actions，M4g 开工前置，只有仓库管理员能做）：`RELEASE_KEYSTORE`（keystore 文件 base64）/ `RELEASE_KEYSTORE_PASSWORD` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD`。
3. **`src-tauri/gen/android/app/build.gradle.kts`**（手工维护，硬约定 2）：加 `signingConfigs.release`，从上述环境变量读取（keystore 路径 / storepass / alias / keypass）；**环境变量缺失时回退 debug 签名**（本地开发流程与 CI 以外的构建完全不受影响）。`release` build type 的 `signingConfig` 指向它。
4. **`release.yml` android job**：加一步解码 `RELEASE_KEYSTORE` secret 为本地文件并导出环境变量 → 构建命令去掉 `--debug`（`pnpm tauri android build --apk --target aarch64`，走真实 release 构建类型）→ 产物路径从 `outputs/apk/universal/debug/` 改为 `outputs/apk/universal/release/`。
5. **一次性迁移成本（该版 release notes 必须写明）**：该版签名从「上一版的 CI debug 钥匙」变为固定 release 钥匙 → 存量 Android 用户还需**最后一次**卸载重装；之后每个版本均可 `adb install -r` 覆盖安装。建议同步 bump `tauri.properties` 的 versionCode（现 20001）保证可装上。
6. **R8 风险（主要技术风险）**：`release` build type 是 `isMinifyEnabled = true` + proguard（`proguard-tauri.pro` 已存在），而 CI 至今只构建过 `--debug`，真实 release 从未构建过——R8 混淆/裁剪可能破坏 native so 加载、WebView、SAF、前台服务等反射路径。构建后必做真机全量回归（见验收）；若出问题，先 `isMinifyEnabled = false` 顶上发版，keep 规则分版本补，不阻塞发版节奏。

**验收（M4g 收尾，真机 REDMI K90 / Android 16）**：

- 连续两次 CI release 构建，两份 APK 的 `apksigner verify --print-certs` 指纹**一致**（固定性证明）
- 真机：装固定签名版（对 v0.2.0 存量用户一次性卸载）→ 出下一版（versionCode+1）→ `adb install -r` **覆盖安装成功**，「应用目录」vault 数据完好
- 真 release 证明：`webview_devtools_remote_<pid>` 不复存在（CDP 不可用）+ `adb shell dumpsys package com.lanmark.app` 无 DEBUGGABLE 标志
- M3 功能全量回归走查（同步循环 / LWW / tombstone / 杀进程 FGS 恢复）通过——R8 风险主验证项

### 12.2 Android release 资产是 debug 包（设计使然，仅文档注明）
