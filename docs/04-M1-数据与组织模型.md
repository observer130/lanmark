## 1. 已确认决策

| 决策点 | 结论 |
|---|---|
| Vault 模式 | **单 vault + 文件夹分区**（存储布局天然兼容将来加多 vault，见 §5） |
| 侧栏功能 | **最近笔记 + 收藏**（在笔记本树之外常驻显示） |
| 文件名规范 | **保留中文（UTF-8）**；空格 → `-`，非法字符剔除 |

## 2. 文件名生成规则

- **中文原样保留**（文件系统/HTTP+JSON/Obsidian 均原生支持 UTF-8）
- 变换：空格 → `-`；剔除 `/ \ : * ? " < > |` 与控制字符；去首尾空格和点；连续 `-` 合并
- 跨平台防护（vault 将来会同步到 Windows 机器）：文件名不得为 Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9，不区分大小写）
- 同名冲突：新建/移动时目标已存在 → 自动追加 `-2`、`-3`…
- **显示名 = 文件名去扩展名**（与 Obsidian 一致）；frontmatter `title:` 仅作为可选覆盖（供"每日笔记"类日期文件名场景用）

## 3. 笔记身份与侧栏

- **笔记身份**：路径即身份（M1）；重命名 = 原子 rename + DB 联动更新（M3 同步协议将引入稳定 id，路径变化不影响同步）
- **最近笔记**：`.lanmark/` DB 表 `recents(path, opened_at)`，打开即记录，上限 50 条
- **收藏**：表 `favorites(path, added_at)`；侧栏拖拽或星标切换；重命名联动

## 4. Vault 布局（重申 + 细化）

```
<vault>/                      ← 单 vault 根目录（App 配置 vaultPath 指向）
├── <文件夹>/…/*.md           ← 目录即层级，无虚拟目录
├── assets/                   ← 附件：内容 sha256 前 16 位命名（a3f8….png），相对路径引用；
│                                附件目录不进目录树（list_tree 跳过，UI 侧隐藏）
└── .lanmark/
    ├── config.json           # vaultPath 所属设备信息（M2 扩展）
    ├── lanmark.db            # SQLite：files 索引 + FTS5(recents/favorites)
    └── trash/                # 回收站（删除永不硬删，铁律）
```

## 5. 多 vault 的预留方式

App 全局配置（`~/.config/lanmark/` 或等价位置）当前只存一个 `vaultPath`。将来支持多 vault 时：配置升级为 vault 列表 + UI 库切换器，每个 vault 目录自带 `.lanmark/` 元数据，**数据零迁移、同步协议零改动**（手机端按 vault 目录粒度多跑一份同步状态即可）。

## 6. 对 M1 任务清单的影响

1. Vault 选择（首次启动选目录 → 写入全局配置）
2. 目录树 CRUD（建/删/重命名文件夹与笔记，rename 走联动）
3. 文件名规范化函数（中文保留 + 跨平台防护）
4. Milkdown 编辑器 + 源码模式（决策门不变）
5. SQLite：files 索引、搜索、recents、favorites
6. 图片粘贴/拖入 → assets/ + 相对引用插入
7. 侧栏：笔记本树 + 最近 + 收藏三段式

## 7. 实现决策记录（M1 实现时）

| 决策 | 说明 |
|---|---|
| **搜索用 LIKE 子串匹配，暂不上 FTS5** | 单人 vault（1e3–1e4 篇）LIKE 全表扫描是毫秒级；FTS5 的 CJK 分词（trigram 要求 ≥3 字符，2 字中文词查不到）会引入复杂度，留到量级上来后在 M4 评估 |
| **编辑器用 @milkdown/crepe**（官方"全家桶"构建，非裸 kit 组装） | Typora 式 WYSIWYG + 斜杠菜单 + 工具栏开箱即用；关掉 AI/Cursor/TopBar，保留 Toolbar/Table/Latex/CodeMirror/ImageBlock；主题 frame-dark |
| **切换笔记/模式 = 销毁重建编辑器** | 避免 ProseMirror 状态重置的边界问题，笔记量级下重建 <200ms，可接受 |
| **图片粘贴**：ImageBlock 的 `onUpload` 处理工具栏上传，剪贴板粘贴另加 DOM `paste` 监听 → `insertImageCommand.run({src})` | Crepe 的 ImageBlock 不处理 clipboard 图片粘贴（只有 "paste link" 占位文案），实测确认 |
| **自动保存**：700ms 防抖；切笔记/关窗口前先落盘 | 写入走 tmp+rename 原子落盘（Rust 侧） |
| **启动自动开库**：`App::setup` 里异步读取全局配置 → 打开上次 vault | 全局配置 `~/.config/com.lanmark.app/config.json`，JSON 键 camelCase（`vaultPath`），与前端 DTO 约定一致 |
| **目录树从文件系统实时 walk**（不缓存文件夹进 DB） | 笔记索引在 DB（供搜索），文件夹结构以磁盘为准，`reindex_vault` 命令手动刷新（侧栏 ⟳ 按钮）；文件 watcher（notify crate）留 M2 |
| **测试策略**：Rust 逻辑 26 个单测全绿（含中文搜索、前缀重命名、回收站、路径逃逸）+ 无头 E2E（预置 vault → 应用自动打开 → 查 DB 验证索引/搜索） | UI 交互（Milkdown/IME/CRUD 点按）由使用者验收 |

## 8. 往返保真：自动化证据（决策门关键项）

`src/milkdown/roundtrip.test.ts`（vitest + jsdom，`pnpm test`，7/7 通过）用**与产品完全相同的 Crepe 构建**验证 md → ProseMirror → md 往返：

| 用例 | 结果标准 |
|---|---|
| 标题/强调/删除线/行内代码/链接/引用/有序无序嵌套列表/hr | 语义等价（列表符号 `-`↔`*`、hr 写法允许归一化） |
| 代码块（内容含 markdown 符号） | **字节级不变** |
| GFM 表格 | 语义等价（分隔行 `---`↔`--` 归一化） |
| 中文正文 + `![alt](assets/x.png)` | **字节级不变**（alt 保留） |
| 无 alt 图片 | **字节级不变**（不产生伪 alt） |
| frontmatter（经产品分离→回填流程） | **字节级不变** |

**为保真做的两个设计决策**（测试驱动发现）：

1. **关闭 Crepe 的 ImageBlock 组件**。其官方序列化把图片缩放比例写进 alt：`![1.00](src)`，且覆盖用户原有 alt（`@milkdown/components` image-block 源码 `alt: \`${ratio.toFixed(2)}\``）。图片改走 commonmark 原生节点：粘贴/拖入 → `insertImageCommand`，或手写 `![](...)`。代价：斜杠菜单无图片项（可接受）。
2. **WYSIWYG 模式剥离 frontmatter**（`src/lib/frontmatter.ts`）：CommonMark 会把 `---` 解析成 hr / setext 标题下划线（实测 `title: x` 被升格成 H2）。打开笔记时 frontmatter 不入编辑器，保存时原样回填；源码模式显示全文可直接编辑。

剩余风险（留待人工验收）：中文 IME 流畅度、真实 WebView 下的渲染/交互（jsdom 覆盖不了）。

## 9b. Obsidian wikilink 语义保护（2026-09-16 轮次 8）

**发现**：Milkdown 对既有 Obsidian 笔记的 `[[wikilink]]` 会转义首括号（`\[\[x]]`）——文字不丢，但 Obsidian 里链接变死链。用户打开真实 Obsidian 库必踩。

**修复**（`src/lib/wikilink.ts`，与 frontmatter 同模式）：
- 进编辑器前 `[[x]]` → `⟦x⟧`、`![[x]]` → `⟦!x⟧`（普通 Unicode，commonmark 无法链接化），保存时按 map **字节级还原**
- WYSIWYG 中显示为 `⟦会议纪要-产品周会⟧`（可读可编辑）；源码模式不受影响
- 4 个单测（链接/嵌入/别名 `[[a|b]]`/同内文不串号/用户手写 ⟦⟧ 不误还原）+ 1 个产品流程字节级往返测试
- 演示库新增 wikilink 示例 + 验收清单第 6 步（Lanmark 保存后 Obsidian 实开验活链接）
- 真·E2E：恢复含 wikilink 的笔记，图片协议正常，**磁盘字节零变化**，JS 零错误
- 前端 37/37，Rust 38/38；CI 连续两 run 三端全绿

## 9c. 编辑器不可编辑事故 + 打开即重写修复（2026-09-16 轮次 9，用户验收反馈）

用户反馈「无法正常输入或编辑」。定位与修复：

**事故 1：tauri dev 下 WYSIWYG 编辑器损坏**
- 根因：`<React.StrictMode>` 的 dev 双挂载（mount→cleanup→mount）与 Crepe 异步 create/destroy 竞争——第一实例创建中被销毁、共享 host DOM 被中途清空，存活实例被污染
- release 构建无 StrictMode，故此前所有无头 E2E 均未复现（教训：E2E 必须覆盖 dev 路径）
- 修复：移除 StrictMode（Tauri 桌面 + 第三方命令式编辑器的标准做法，main.tsx 有注释）；MilkdownHost 改为每次挂载**专属 inner root**（cleanup 时整体移除），双挂载也不互相踩踏

**事故 2：打开笔记即重写文件（cosmetic）**
- 现象：带 `- [ ]` 任务列表的笔记打开 1 秒后被重写（`-`→`*`、补尾行）
- 根因：Crepe create() 后会异步触发一次**同 doc 重序列化**的 markdownUpdated（commonmark 列表序列化用 `*`），此前的 suppressChange 窗口只覆盖图片改写 dispatch，盖不住这个后续事件
- 修复：改为**基线文档判定**——记录 create+改写后的 doc 为基线，`doc.eq(基线)` 的更新一律抑制（伪事件），doc 真实变化才放行并刷新基线。语义精确，无时间窗、无吞编辑风险
- 验证：dev 模式打开任务列表笔记 40s 磁盘 md5 零变化；程序化插入文本（模拟真实编辑）正常落盘；release 回归零变化

## 10. 真实 WebView 验证 + vault 协议（2026-09-16 轮次 3）

**发现并修复**：无头 E2E 日志抓到图片请求打到 Tauri 内置 asset 协议（`Asset 'assets/x.png' not found; fallback to index.html`）——**笔记里的图片在 App 内必然裂图**（相对路径被 WebView 按 App 自身 URL 解析）。

修复方案（源文件零侵入）：
- **`vault://` 自定义协议**（`src-tauri/src/protocol.rs`，Builder 注册）：`vault://localhost/<vault相对路径>` → 校验（safe_join 防逃逸）→ 读文件 → 按扩展名 content-type；5 个单测（含中文路径 percent-decode、越权拒绝、无 vault 404）
- **编辑器内图片 src 双表示**（`src/lib/vault-url.ts` + EditorPane）：文档树里存 vault 协议 URL（显示用），保存时 `vaultUrlsToRelative` 还原为**相对笔记目录**的引用（Obsidian 约定：子目录笔记 → `../assets/x.png`）；12 个单测
- 粘贴/拖入图片：插入时直接用协议 URL，保存即还原为规范相对引用
- 放弃过 `<base href="vault://localhost/">` 方案：会连 App 自身资源（/assets/*.js）一起改走 vault 协议，生产环境直接白屏

**新增强化**：
- `tauri-plugin-log`（stdout + 日志文件）：WebView console 可观测，M2 同步调试必需
- 启动恢复上次打开的笔记（静默降级：文件已删不报错）

**真实 WebView E2E 证据**（release 二进制，30s 存活）：

全链路：自动开库 → 恢复最近笔记 → Crepe 启动 → `../assets/deadbeef.png` 解析 → 协议请求 → 200 提供，JS 零错误。

## 11. 移动端编译修复 + 中文图片引用编码 bug（2026-09-16 轮次 5）

**Android CI 自 M1 首提交（2642607）起持续失败**，本地复现定位：
- `tauri-plugin-dialog` 的 `blocking_pick_folder` 是 `#[cfg(desktop)]` API，移动端不存在（JS 版 `open({directory:true})` 在 Android 直接 `FolderPickerNotImplemented`）
- 修复：对话框与业务彻底解耦——Rust 只收路径（`vault_set_path(path, mode)`），选择由前端完成：桌面走 JS dialog；移动端 M1 回退 app 文档目录（M2 换 SAF 选择器）。本地 Android APK 构建验证通过

**中文图片引用编码 bug（数据损坏级，已修复）**：
- 现象：每次启动，磁盘上的 `![x](../assets/示例图片.png)` 中文引用多叠一层 percent-encoding
- 根因 1：`fromVaultUrl` 只剥前缀不解码，与 `toVaultUrl` 的编码不对称 → 自动保存把编码后的引用写回文件
- 根因 2：启动期图片 URL 改写的 `dispatch` 会触发 `markdownUpdated` → 打开笔记即变脏 → 700ms 防抖落盘重写文件
- 修复：`fromVaultUrl` 逐段 `decodeURIComponent`（对称性单测）；`suppressChange` 标志抑制启动期改写产生的变更事件
- 证据：双启动 E2E，vault 协议两次正确解码提供图片，**全部 md 文件 md5 前后零变化**，磁盘引用保持原始未编码
