# 02 · 技术选型与工程路线

> 项目代号：**Lanmark** —— 局域网 markdown 笔记（Windows / Linux / Android，手机为中心节点）
> 前置文档：《01-可行性评估与需求确认》

---

## 1. 选型结论（TL;DR）

| 层 | 选型 | 说明 |
|---|---|---|
| 跨端框架 | **Tauri 2** | 一套 Rust core + 一套 Web 前端 → 三端 |
| 前端 | **TypeScript + React + Vite** | 生态最大、学习资料最多、AI 辅助开发效率最高 |
| 编辑器 | **Milkdown**（Typora 风格 WYSIWYG，ProseMirror + remark，输出真实 markdown）；**备选 Vditor** | 决策门设在 M1 末（见 §5） |
| UI/状态 | Tailwind CSS + Zustand | 简单直接，无重框架包袱 |
| 数据 | 文件系统（`.md` + `assets/`）+ **SQLite**（rusqlite + FTS5） | 索引、搜索、同步元数据 |
| 同步服务器 | **Rust axum**（App 进程内嵌）+ `mdns-sd` mDNS | 同一份代码编译到三端，为"任意端可为中心"铺路 |
| Android 后台 | **`tauri-plugin-background-service`**（前台服务，`specialUse` 类型） | 备选：自写小段 Kotlin 服务 |
| 同步协议 | HTTP + JSON，Bearer token 鉴权，文件级版本比对 | 见 §3 |

**为什么是 Tauri 2 而不是 Flutter / Compose Multiplatform（决定性因素）**：
需求中"所见即所得（Typora 风格）"是编辑器要求最高的形态。ProseMirror 生态（Milkdown/TipTap）是唯一成熟的 markdown 原生 WYSIWYG 路线，且能**往返保真**（编辑后还原为真实 markdown，而非自定义格式）；Flutter 的编辑器生态（AppFlowy Editor 等）fidelity 不足且 `flutter_markdown` 官方包已停维护；Compose Multiplatform 基本空白。同时 Tauri 的 Rust core 三端共用——**同步服务器代码在桌面端也天然可用**，"任意端可为中心"的演进几乎免费。

## 2. 系统架构

```
┌────────────────────────── 同一套 Tauri App（三端） ──────────────────────────┐
│                                                                             │
│  前端 (TS/React, WebView)                 Rust Core (三端同一份代码)          │
│  ┌────────────────────────┐              ┌─────────────────────────────┐    │
│  │ UI（三栏：目录/编辑/预览）│  Tauri 命令/事件 │ vault：文件读写、hash、watcher │    │
│  │ Milkdown WYSIWYG 编辑器  │◄────────────►│ db：SQLite 索引 + FTS5        │    │
│  │ 源码模式兜底 (CodeMirror) │              │ server：axum 同步 API + mDNS │    │
│  │ sync client 同步客户端   │              │ pairing：QR/token 管理        │    │
│  └────────────────────────┘              └─────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────────────┘
          │                                                        │
          │ 桌面端：纯客户端                                         │ Android 端：客户端 + 中心节点
          ▼                                                        ▼
   其他设备上的 axum 服务器  ◄──── 局域网 HTTP + mDNS ────►  前台服务保活 (specialUse)
```

**职责划分原则**：
- 同步**客户端**逻辑放 TypeScript（三端前端一致，只调 Tauri 命令做文件/DB 操作）
- 同步**服务器**放 Rust（axum），MVP 只在 Android 端启用，代码不区分平台
- Rust 面积刻意收小（学习曲线管理，见 §6 风险 7）

## 3. 数据与同步协议设计

### 3.1 Vault 目录结构（兼容 Obsidian）

```
vault/
├── 笔记本A/
│   ├── 笔记1.md            # 引用图片用相对路径 assets/xxx.png
│   └── 子笔记本/
├── assets/                 # 附件统一存放，文件名为内容 hash
│   └── a3f8….png
└── .lanmark/
    ├── config.json          # 设备 ID、设备名、已配对设备
    ├── lanmark.db           # SQLite：文件索引 + FTS5 全文 + 同步元数据
    └── trash/               # 回收站（铁律：删除先进这里）
```

### 3.2 同步模型（文件级版本比对 + 冲突保留两份）

- 每个文件的状态：`{path → (content_hash, version_vector, deleted_tombstone)}`
- **中心节点**（手机）持有权威状态；客户端带本地 vector 发起同步
- 一轮同步：
  1. `POST /sync/manifest` —— 客户端上报本地变更摘要
  2. 服务器返回：需下载（服务器新）、需上传（客户端新）、**冲突（双向都改）**
  3. 差量传输内容；冲突时服务器保留两份，来件重命名为 `笔记名.conflict-<设备名>-<时间>.md`
- 删除 = 打 tombstone + 移入 `.lanmark/trash/`，**永不硬删**
- 客户端触发时机：启动时、定时（可配）、检测到本端变更、mDNS 发现服务器上线

### 3.3 发现 / 配对 / 安全

- 发现：mDNS 广播 `_lanmark._tcp.`（服务端）；客户端浏览局域网内所有 Lanmark 中心
- 配对：手机端展示二维码 `{ip, port, token, deviceName}`，桌面扫码或手输 → token 存入本机
- 鉴权：`Authorization: Bearer <token>`（配对时颁发，可吊销）
- 传输加密：MVP 为局域网内 HTTP + token（家庭网络威胁模型下可接受）；M4 加固为自签 TLS（rcgen + rustls）+ 配对时证书固定
- Android 明文 HTTP：`networkSecurityConfig` 放行局域网明文（或直接上自签 TLS）

## 4. 工程路线（里程碑）

> 节奏按"单人 + AI 辅助开发、边学边做"估算，供参考不设死线。

### M0 · 脚手架与三端贯通（第 1 周）
- Monorepo：`src/`（TS 前端）、`src-tauri/`（Rust core）、`docs/`
- Tauri 2 + React + Vite 跑通桌面 `tauri dev`；Android APK 真机安装启动
- 前后端命令桥双向 hello；CI 产出三端构建物
- **验收：手机上看到 App 界面，桌面命令调用 Rust 返回成功**

### M1 · 单机笔记核心（第 2–4 周）⭐ 决策门
- Vault 选择/管理、文件夹层级 CRUD、笔记增删改名
- **Milkdown WYSIWYG** 编辑 + 自动保存（防抖）+ 源码模式兜底（CodeMirror 6）
- SQLite 索引 + FTS5 全文搜索；图片粘贴/拖入 → 存 `assets/` 并插入相对引用
- **决策门：Milkdown 集成受阻（往返保真或 IME 问题严重）→ 切换 Vditor（Typora 式 IR 模式、中文文档、开箱即用）**
- **验收：桌面端完整走通"建目录 → 写图文笔记 → 搜索到它"，且 .md 文件用 Obsidian 打开正常**

### M2 · Android 化 + 手机服务器（第 5–7 周）
- M1 功能 Android 端对齐（布局适配、移动端编辑体验）
- axum 同步服务器内嵌 + mDNS 广播；前台服务（`tauri-plugin-background-service`，`specialUse`）
- 电池优化白名单 / 自启动引导页；二维码配对（手机出码、桌面扫码）
- **验收：手机息屏 30 分钟后服务器仍在线；桌面可发现并配对成功**

### M3 · 同步引擎（第 8–10 周）⭐ 核心里程碑
- 自动同步循环（周期/保存后/前台恢复/上线恢复，开关联动默认开）+ 断线退避重连
- 删除传播（tombstone，铁律安全）+ 多端基线修复（桌面×2 + 手机×1 收敛）
- 冲突裁决：mtime LWW 较新者留原路径、较旧者自动保留为可见冲突副本（对标 Dropbox/Syncthing，无人工解析）；同步状态 UI（在线状态、最近同步时间、合并报告）
- 扫码配对移至 M4（2026-09-19 用户定）
- 设计细节、用户决策与协议 v1.1 见 [docs/07](07-M3-同步引擎深化设计.md)
- **验收：三端收敛；离线改动恢复网络后自动同步；冲突 diff 解析并跨端传播；删除跨端传播；服务器恢复自动续同步（docs/07 §10）**

### M4 · 加固与分发（第 11–12 周）
- 打包分发：Windows NSIS/MSI、Linux deb/AppImage、Android APK（侧载指南）
- 安全加固：自签 TLS + 证书固定；回收站清理策略； vault 手动备份/整体导出
- 错误日志、设置页完善、README 与使用文档
- **验收：三端安装包在新设备上按文档 15 分钟内完成安装-配对-同步全流程**

### 二期候选（MVP 后）
标签/双链、历史版本、导出 PDF/HTML、桌面端也可当中心节点（协议已预留）、CRDT 段落级合并评估

## 5. 编辑器决策门（M1 末执行）

| 项 | 主选 Milkdown | 备选 Vditor |
|---|---|---|
| 形态 | Typora 风格 WYSIWYG（ProseMirror + remark） | 即时渲染（IR）模式，Typora 风格 |
| 输出 | 真实 markdown，往返保真好 | markdown 往返 |
| 集成成本 | 高：React 集成偏裸、UI 需自建 | 低：开箱即用，中文文档 |
| 判定标准 | M1 内完成：加载/保存往返无损、中文 IME 正常、图片粘贴 | 若 Milkdown 判定失败则切换 |
| 维护状态 | 11.7k★，2025 年仍活跃 | 活跃，国内生态 |

## 7. 你需要学的最小技术集（配合 AI 辅助开发）

1. **TypeScript + React 基础** —— 组件、state、hooks（第 1–2 周边做 M0/M1 边学）
2. **pnpm / Vite / npm 生态** —— 跑工程即可，无需深入
3. **Rust 基础** —— 所有权、`Result`、async/tokio 初步（M2 前够用即可，core 代码可与 AI 结对完成）
4. **Kotlin** —— 零散接触即可（仅当需要自写前台服务兜底）
5. **概念** —— mDNS、前台服务、SQLite/FTS5、版本向量（文档已覆盖，遇到再查）
